## Теория

### Программа перестаёт быть списком

**Как было.** Программа шла сверху вниз: спросить → посчитать → напечатать → конец. Дошла до последней строки и закончилась.

**Как стало.** Окно висит и ждёт. Код срабатывает, только когда что-то произошло: нажали кнопку, закрыли окно, нажали клавишу.

Это главное, что должно остаться с урока. Виджеты — мелочь, а вот эта смена устройства программы — нет.

### Одна строчка, которая держит окно

```python
window.mainloop()
```

**Что делает.** Бесконечно ждёт: не нажали ли кнопку, не закрыли ли окно. Это тот же `while` из первого урока, только писать его не нужно.

**Где писать.** Всегда самой последней строкой файла. Всё, что написано после неё, выполнится только когда окно закроют.

Забытый `mainloop` — окно мигнёт и исчезнет.

### Виджет создаётся в два шага

Сначала создаём, потом кладём в окно через `pack()`. Это две разные строки.

Забыли `pack()` — виджет есть в программе, но его не видно.

Первое слово в скобках при создании — `window`. Это значит «положить внутрь этого окна».

### command — главная ловушка урока

| Запись | Что происходит |
|---|---|
| `command=check_connection` | **Правильно.** Даём кнопке имя функции. Она вызовет её, когда её нажмут. |
| `command=check_connection()` | **Ошибка.** Со скобками функция выполнится сразу, при запуске программы. А кнопка потом не сработает ни разу. |

Функцию пишем **выше** кнопки.

### config меняет то, что уже есть

`label.config(text="...")` меняет уже существующую надпись. Новую создавать не нужно.

Вот теперь программа по-настоящему работает в окне: до этого вывод уходил в терминал, а сейчас меняется то, что человек видит.

### Резерв: счётчик нажатий

```python
import tkinter as tk

window = tk.Tk()
window.title("ProTeam Labs")
window.geometry("400x250")

label = tk.Label(window, text="Терминал студии", font=("Arial", 16))
label.pack(pady=20)

count = 0


def check_connection():
    global count
    count = count + 1
    label.config(text="Проверок: " + str(count))


button = tk.Button(
    window,
    text="Проверить связь",
    font=("Arial", 14),
    command=check_connection
)
button.pack(pady=10)

window.mainloop()
```

**`global`.** Без этой строки функция заведёт свой собственный `count` и забудет его сразу после нажатия. `global` говорит: бери тот, что снаружи.

**`str(count)`** — потому что склеить текст с числом напрямую нельзя. Это та же история, что с задачей на 5 SP.

```python
button = tk.Button(window, text="Проверить", command=check_connection)
```

## Зачем это в реальных программах [НОВОЕ]

**Главный цикл есть везде.** `mainloop()` в tkinter, игровой цикл в pygame, event loop в браузере. Любая программа, которая не заканчивается сама, а ждёт действий человека, устроена одинаково: бесконечный цикл, который проверяет, не случилось ли чего.

**Обработчик события — это и есть `command`.** В веб-странице кнопка делает `onclick="функция"`. В Unity на кнопку вешают метод. В мобильных приложениях — то же самое. Везде один принцип: ты даёшь системе **имя** функции, а она вызывает её сама, когда придёт время.

**Разделение «что показать» и «что посчитать».** `label.config()` меняет то, что видит человек, а функция считает. В больших программах это разделение называют MVC, и оно работает ровно по той же логике: данные отдельно, экран отдельно.

## Идеи мини-игр для сайта [НОВОЕ]

**«Со скобками или без».** Показываем строку с `command=`, игрок выбирает один из двух вариантов. После ответа — что произойдёт в каждом случае. 8–10 карточек подряд, считается скорость.

**«Собери окно».** Даны строки кода вразбивку: `import`, `tk.Tk()`, создание `Label`, `pack()`, `mainloop()`. Надо расставить в правильном порядке перетаскиванием. Проверка: `mainloop` обязательно последним, `pack` после создания виджета.

**«Что увидит пользователь».** Показан код из 5–7 строк, три варианта картинки окна. Выбрать правильную. Ловушки: забытый `pack` (пустое окно), `mainloop` в середине, два виджета без отступов.

## Теория

### Что заменяет input()

| В терминале | В окне |
|---|---|
| `answer = input("Число: ")` | `answer = entry.get()` |
| Программа останавливается и ждёт, пока человек напечатает и нажмёт Enter. Всё это время больше ничего не происходит. | Программа ничего не ждёт. Человек печатает когда хочет, а мы забираем текст из поля в тот момент, когда нажали кнопку. |

Ключевая разница: `input` останавливает программу, `get` — нет. Окно живёт всё время.

### Три детали в окне

| Виджет | Роль | Что делает |
|---|---|---|
| `Entry` | Поле ввода | Человек печатает сюда. Мы читаем это через `.get()` |
| `Button` | Кнопка | Момент, когда мы решаем забрать текст из поля |
| `Label` | Надпись | Сюда кладём ответ. Меняется через `.config()` |

### entry.get() всегда возвращает строку

Даже если человек напечатал цифры. Поэтому `int()` обязателен. Та же история, что была с калькулятором на первом уроке.

### Цвет текста

`fg` — цвет текста надписи. Можно писать словами — `"green"`, `"red"`, `"orange"`. А можно кодом цвета: `fg="#38BD60"`. Фирменные цвета студии как раз такие.

### randint

`random.randint(1, 100)` — оба конца входят, сотня тоже может выпасть.

## Код урока

### Шаг 1. Окно и поле ввода

```python
import tkinter as tk
import random

secret = random.randint(1, 100)

window = tk.Tk()
window.title("Угадай число")
window.geometry("420x300")

title = tk.Label(window, text="Я загадал число от 1 до 100", font=("Arial", 15))
title.pack(pady=20)

entry = tk.Entry(window, font=("Arial", 20), width=8, justify="center")
entry.pack()

result = tk.Label(window, text="", font=("Arial", 16))
result.pack(pady=20)

window.mainloop()
```

**Проверить:** в поле можно печатать. Больше пока ничего не происходит.

**Обратить внимание:** `result` создаётся с пустым текстом. Надпись есть, но её не видно — появится, когда в неё что-то положат.

Файл называем `game.py`. Не `random.py`.

### Шаг 2. Кнопка и проверка

```python
import tkinter as tk
import random

secret = random.randint(1, 100)

window = tk.Tk()
window.title("Угадай число")
window.geometry("420x300")

title = tk.Label(window, text="Я загадал число от 1 до 100", font=("Arial", 15))
title.pack(pady=20)

entry = tk.Entry(window, font=("Arial", 20), width=8, justify="center")
entry.pack()

result = tk.Label(window, text="", font=("Arial", 16))
result.pack(pady=20)


def check():
    answer = int(entry.get())

    if answer == secret:
        result.config(text="Точно!", fg="green")
    elif answer < secret:
        result.config(text="Моё число больше", fg="red")
    else:
        result.config(text="Моё число меньше", fg="red")


button = tk.Button(window, text="Проверить", font=("Arial", 14), command=check)
button.pack()

window.mainloop()
```

**Проверить:** ввести число, нажать. Ответ появляется зелёным или красным.

### Шаг 3. Счётчик попыток

```python
tries = 0


def check():
    global tries
    tries = tries + 1

    answer = int(entry.get())

    if answer == secret:
        result.config(text="Угадал за " + str(tries) + " попыток!", fg="green")
    elif answer < secret:
        result.config(text="Моё число больше. Попытка " + str(tries), fg="red")
    else:
        result.config(text="Моё число меньше. Попытка " + str(tries), fg="red")
```

`global` — тот же, что в кликере на прошлом уроке. Без него счётчик каждый раз начинается с нуля.

### Шаг 4. Кнопка «Заново»

```python
def restart():
    global secret, tries
    secret = random.randint(1, 100)
    tries = 0
    result.config(text="Загадал новое число", fg="black")
    entry.delete(0, "end")


restart_button = tk.Button(window, text="Заново", font=("Arial", 12), command=restart)
restart_button.pack(pady=10)
```

`entry.delete(0, "end")` — очистить поле от первого символа до последнего.

Через запятую можно объявить сразу два `global`. Забудете `secret` — число не поменяется, и игра станет скучной.

### Полный файл

```python
import tkinter as tk
import random

secret = random.randint(1, 100)
tries = 0

window = tk.Tk()
window.title("Угадай число")
window.geometry("420x300")
```

## Ошибки, которые делали на уроке

### Счётчик всегда показывает 1

**Неправильно:**
```python
def check():
```

```python
def check():
```

**Неправильно:**

## История урока

### 1957. Компьютер не умеет наугад

В Британии собрали машину ERNIE — шкаф размером с комнату, который умел ровно одно: выбирать числа наугад.

Обычный компьютер выбирать наугад не умеет. Он считает по формуле — а формула всегда даёт один и тот же ответ.

ERNIE брал случайность снаружи — из электрического шума в лампах. Его числа до сих пор разыгрывают британскую лотерею.

**Вопрос классу до объяснения:** а как компьютер вообще может выбрать наугад? Обычно отвечают «ну он просто выбирает».

---

## Зачем это в реальных программах [НОВОЕ]

**Формы — это то же самое.** Регистрация на сайте, ввод адреса в доставке, поиск в магазине: поле, кнопка, ответ. Разница только в количестве полей.

**Случайные числа в играх.** Выпадение лута, критический урон, разброс пуль, генерация уровней в Minecraft — всё это `randint` и его родственники. Там же появляется понятие **seed**: если задать одно и то же стартовое число, мир сгенерируется одинаковым. Поэтому в Minecraft можно поделиться сидом и получить ту же карту.

**Цвет как сигнал.** В интерфейсах зелёный и красный — не украшение, а способ передать результат быстрее, чем человек успеет прочитать текст. Поэтому форма регистрации подсвечивает неправильное поле красным, а не пишет внизу абзац.

## Идеи мини-игр для сайта [НОВОЕ]

**«Угадай за сколько».** Браузерная версия игры с урока: компьютер загадывает число от 1 до 100, игрок угадывает. Внизу показывается, сколько попыток осталось до «оптимальных десяти». Учит делить диапазон пополам.

**«Строка или число».** Карточки с выражениями: `entry.get()`, `int(entry.get())`, `"5" + "5"`, `5 + 5`, `str(5) + "5"`. Игрок выбирает, что получится: число, строка или ошибка. Проверка с объяснением.

## Теория

### pack кладёт стопкой, grid — в клетки

`pack()` кладёт всё друг под другом по центру. Подпись и поле не стоят рядом.

`grid()` расставляет по строкам и столбцам. Подпись слева, поле справа, всё в линию.

**В одном окне их мешать нельзя.** Окно просто не нарисуется, ошибки при этом не будет.

### Три слова про grid

| Параметр | Что делает | Подробнее |
|---|---|---|
| `row`, `column` | Номер строки и столбца | Отсчёт с нуля, как у списков |
| `columnspan` | Растянуть на несколько клеток | Так заголовок встаёт по центру над обоими столбцами |
| `sticky="e"` | Прижать к краю клетки | `e` — east, восток. Без этого подписи болтаются по центру |

Ещё есть `padx` и `pady` — отступы внутри клетки.

### float, а не int

Суммы бывают дробные. `int` отрезал бы всё после точки, и 99.90 превратилось бы в 99.

### Как заставить число выглядеть прилично

| Как пишем | Что выводится |
|---|---|
| `str(dollars)` | `33.33333333333333` |
| `f"{dollars:.2f}"` | `33.33` |
| `f"{dollars:.2f} $"` | `33.33 $` |

`:.2f` означает «две цифры после точки». Склеивать плюсами больше не нужно.

### Курс вводит человек, а не код

Если записать курс прямо в код, через месяц программа начнёт врать. Поэтому курс — это данные, а не часть программы.

Это правило работает везде: то, что меняется, в код не зашивают.

### Три окна — три разных смысла

| Вид | Когда | Что происходит дальше |
|---|---|---|
| `showerror` | Считать невозможно. Буква вместо числа | Программа не может продолжить |
| `showwarning` | Данные неправильные. Минус сто рублей | Понять можно, посчитать нельзя |
| `showinfo` | Посчитаем, но предупредим. Миллион рублей | Считаем дальше, просто уточняем |

Главное: всплывашку человек обязан закрыть. Поэтому их не ставят на каждый чих.

```python
from tkinter import messagebox


def get_values():
    try:
        amount = float(amount_entry.get())
        rate = float(rate_entry.get())
    except ValueError:
        messagebox.showerror("Ошибка", "Введите числа, а не текст")
        return None, None

    if amount < 0:
        messagebox.showwarning("Так нельзя", "Сумма не может быть меньше нуля")
        return None, None

    if rate <= 0:
        messagebox.showwarning("Так нельзя", "Курс должен быть больше нуля")
        return None, None

    if amount > 1000000:
        messagebox.showinfo("Проверьте", "Сумма подозрительно большая. Не лишний ли ноль?")
```

```python
button_eur = tk.Button(window, text="В евро", font=("Arial", 13), command=to_euro)
button_eur.grid(row=6, column=0, columnspan=2, pady=10)
```

**+1 SP. Пробелы в тысячах.** Вывести `1 234 567.89` вместо `1234567.89`.

```python
text = f"{rubles:,.2f}"
text = text.replace(",", " ")
result.config(text=text + " руб", fg="green")
```

`:,.2f` ставит запятые между тысячами, а `replace` меняет их на пробелы — у нас так принято писать.

**+2 SP. Поменять местами.** Кнопка меняет значения двух полей.

```python
def swap():
    a = amount_entry.get()
    r = rate_entry.get()

    amount_entry.delete(0, "end")
    rate_entry.delete(0, "end")

    amount_entry.insert(0, r)
    rate_entry.insert(0, a)


swap_button = tk.Button(window, text="Поменять местами", font=("Arial", 12), command=swap)
```

Тонкость: сначала забираем **оба** значения, потом чистим. Если чистить по очереди, второе значение потеряется.

## Ошибки, которые делали на уроке

### Окно открылось пустым

**Неправильно:**
```python
title.grid(row=0, column=0)
amount_entry.pack()
```

Что происходило: окно пустое, ничего не видно, ошибки нет. Смешаны `grid` и `pack`.

**Правильно:** в одном окне — только один способ.

### Всё съехало влево

**Неправильно:**
```python
amount_label.grid(row=1, column=0, padx=10, pady=8)
```

Подписи болтаются по центру своей клетки, строй разъезжается.

**Правильно:**
```python
amount_label.grid(row=1, column=0, padx=10, pady=8, sticky="e")
```

### Кнопки встали друг под другом

**Неправильно:**
```python
button_usd.grid(row=3, column=0)
button_rub.grid(row=4, column=0)
```

**Правильно:** один `row`, разные `column`.
```python
button_usd.grid(row=3, column=0)
button_rub.grid(row=3, column=1)
```

### 150.5 вместо 150.50

Забыт `:.2f`.

### TypeError: unsupported operand

**Неправильно:**
```python
def to_dollars():
    amount, rate = get_values()
    dollars = amount / rate
```

Что происходило: если `get_values` вернула `None, None`, программа падала на делении.

**Правильно:**
```python
def to_dollars():
    amount, rate = get_values()
    if amount is None:
        return

    dollars = amount / rate
```

### Всплывашка появляется дважды

**Неправильно:**
```python
def to_dollars():
    if get_values()[0] is None:
        return
    amount, rate = get_values()
```

`get_values()` вызвана два раза — значит, и проверки выполнились дважды.

**Правильно:** вызвать один раз, результат запомнить. Это ровно то же правило, что и с `entry.get()`.

## История урока

### Копейка, которой нет

```
>>> 0.1 + 0.2
0.30000000000000004
```

Это не ошибка Python. Так считает любой компьютер в мире.

Дробные числа компьютер хранит приблизительно — как 1/3 нельзя записать десятичной дробью до конца.

Поэтому в банках деньги никогда не хранят дробными числами. Хранят в копейках, целыми. Иначе на миллионе операций накапливаются лишние копейки, и их кто-то замечает.

**Показать живьём в терминале.** Эффект сильный, дети не верят глазам.

## Зачем это в реальных программах [НОВОЕ]

**Сетка — основа любого интерфейса.** `grid` в tkinter, CSS Grid в вебе, Auto Layout в Figma, Grid Layout в Unity. Везде одно и то же: экран делится на строки и столбцы, элементы занимают клетки.

**Валидация ввода.** Любая форма в интернете проверяет данные по тем же правилам: сначала формат (это вообще число?), потом смысл (а число-то разумное?). Банковские приложения действительно переспрашивают при подозрительно большой сумме — это тот самый `showinfo`.

**Проблема дробных чисел — настоящая.** В финансовых системах суммы хранят целыми числами в минимальных единицах (копейках, центах). В играх с этим сталкиваются при подсчёте урона и процентов: 0.1 + 0.2 != 0.3, и здоровье игрока может застрять на 0.0000001.

## Идеи мини-игр для сайта [НОВОЕ]

**«Расставь по клеткам».** Пустая сетка 2×4 и список виджетов. Перетаскиванием расставить так, чтобы получилась форма из урока. Проверка: совпали ли `row` и `column`.

**«Какая всплывашка».** Даны ситуации: «пользователь ввёл букву», «ввёл минус сто», «ввёл миллион», «ввёл ноль в курс». Выбрать `showerror`, `showwarning` или `showinfo`. С объяснением после ответа.

**«Сколько знаков».** Показано выражение и варианты вывода. Например, `f"{1/3:.2f}"` → `0.33` / `0.3333` / `0.33333333`. Десять карточек на скорость.
